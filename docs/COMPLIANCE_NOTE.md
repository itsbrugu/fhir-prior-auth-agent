# Compliance Note

**This project contains zero real patient data.**

Every patient bundle in [`data/patients/`](../data/patients) was generated by
[Synthea](https://github.com/synthetichealth/synthea) (MITRE, Apache-2.0), an
open-source synthetic patient generator that never touches real health
records. Names, dates of birth, addresses, and clinical histories are
statistically realistic but entirely fabricated. Synthea intentionally
appends numbers to first/last names (e.g. `Boyd728`) precisely so nobody
mistakes its output for a real person.

Because none of this is real patient data, HIPAA does not technically apply
to this project. It is nonetheless architected as if it did:

- The deterministic coverage-rules layer ([`backend/rules/prior_auth_rules.yaml`](../backend/rules/prior_auth_rules.yaml))
  makes every policy decision auditable and independent of the LLM -- the
  LLM explains a decision, it never makes or overrides one.
- Every step the agent takes is timestamped and persisted
  ([`backend/app/store.py`](../backend/app/store.py)), retrievable via the
  API for a full audit trail.
- Secrets (the Anthropic API key) are read from environment variables only,
  never hardcoded, and `.env` is gitignored.

## Disclosed data augmentation

Two of the four demo patients ship with **one additional synthetic FHIR
resource** appended by [`scripts/finalize_demo_patients.py`](../scripts/finalize_demo_patients.py),
because Synthea's generic disease modules produce realistic Condition entries
(e.g. "Chronic low back pain") without always generating the specific
downstream evidence (a documented physical-therapy course, an MRI report) a
utilization-management reviewer would look for. Adding that evidence lets the
demo show a clean APPROVE path in addition to the PEND/DENY paths that occur
naturally. This is disclosed in the script's own docstring and here --
nothing about any of these four patients was ever real to begin with.

## Scope not covered here

- The rules layer is *inspired by* the Da Vinci CRD/PAS implementation
  guides, not a full CDS Hooks / PAS IG implementation. See
  [`ARCHITECTURE.md`](ARCHITECTURE.md) for the honest gap between this demo
  and a production-grade implementation.
- This is a local demo, not a deployed or externally-accessible system. No
  real credentials, PHI, or production infrastructure are involved.
